# 운영자 설정 (8-A)

## 1. 기본값은 data/*.json 그대로, 바꾼 키만 user://settings.json에 덮어쓰기
- **선택:** 설정 파일에는 운영자가 바꾼 키만 저장하고, 읽을 때 `data/*.json` 값 위에 얹는다. 기본값과 같아지면 저장 대상에서 뺀다.
- **이유:** 안 바꾼 키는 `feel.json`·`economy.json`을 고치면 계속 반영된다(사용자가 직접 손보는 값이 많아서). 바꾼 키만 설정이 우선하고, 설정 화면에서는 노랑으로 보여 "고쳐도 안 바뀌는 키"를 알 수 있다.
- **다른 후보:** 모든 키를 통째로 저장(처음 저장한 값이 박혀서 json을 고쳐도 영영 반영 안 됨).

## 2. 시작 화면에서만 연다 (게임 중 열기는 이번에 하지 않음)
- **선택:** 시작 화면 숨김 키 F2. 설정이 열려 있는 동안 키 입력은 시작 화면이 설정 화면에 넘겨 한 곳에서 처리한다(Esc가 게임 종료로 새지 않음).
- **이유:** 시작 화면에는 진행 중인 판이 없어서 "릴·AUTO·정산 연출·GAME OVER 중 잠금", "일시정지", "진행 중인 판의 시작 크레딧·CONTINUE 횟수 변경"이 생기지 않는다. 7-B 불변식(`grant_credit` 경유, 결과는 START 순간 확정)을 건드리지 않는다.
- **다른 후보:** 게임 중에도 열기(main 안 오버레이 + 일시정지 + 잠금 조건). 별도 단계로 미룸.

## 3. 테스트 격리: 설정 사용 스위치 + 합치는 지점 한정
- **선택:** `UserSettings.enabled`는 헤드리스에서 기본 꺼짐. 설정을 합치는 곳은 앱 진입점(오토로드 `_ready`, 시작 화면, `main._ready`/`reload_feel`)뿐이고 `FeelConfig.load_from_file`·`GameState.initialize`·`BalanceData`는 순수하게 둔다. 테스트는 시작할 때 `configure(false)`를 명시하고, 저장 테스트는 `user://settings_test*/` 격리 폴더만 쓴다.
- **이유:** sim·match_test·logic_test는 아예 영향을 받지 않고, GUI로 테스트를 돌려도 개발자 PC의 실제 설정 파일이 테스트 결과를 바꾸지 않는다. 테스트 뒤 실제 user 폴더에 파일이 남지 않음을 확인했다.

## 4. 최고 기록은 설정과 별도 파일, 기록 시점은 GAME OVER + 창 닫기
- **선택:** `user://highscore.json`에 `best_peak_credit` 하나. GAME OVER가 될 때와 창 닫기 요청 때 한 판(NEW GAME 이후)의 최고 크레딧을 기록하고, 더 클 때만 저장하며 `run_tainted` 판은 제외한다.
- **이유:** "설정 기본값으로 되돌리기"가 기록을 지우지 않게 분리했다. 새 최고치마다 즉시 저장하면 파일을 자주 쓰고 COIN을 쓴 판의 처리가 복잡해진다.

## 5. BGM 켜기/끄기는 설정 파일 전용 키 + 버스 mute
- **선택:** `bgm_enabled`(기본 켜짐)를 설정 파일에만 두고(data/*.json 키 추가 없음) BGM 오디오 버스를 mute한다.
- **이유:** `BgmPlayer` 로직을 건드리지 않고 즉시 반영된다.

## 6. 설정 화면의 노드는 트리에 들어간 뒤에 만든다
- **발견:** 글자가 있는 노드(Label·Button)는 트리에 들어가기 전에 크기를 지정하면 기본 글꼴 기준의 큰 최소 크기(예: 높이 23·31)가 남아 요청한 크기보다 커진다.
- **선택:** `SettingsScreen`의 탭·하단 버튼·안내 글자는 `_ready()`에서, 줄은 부모에 넣은 뒤에 크기를 정한다. 화살표·실행 버튼 높이는 테마 최소 높이(26)에 맞췄다.
