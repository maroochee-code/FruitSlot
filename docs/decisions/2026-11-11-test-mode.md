# 테스트 모드 (8-B)

## 1. 켜기는 시작 화면 F3, 저장하지 않고 매번 꺼진 채 시작
- **선택:** `GameState._ready()`가 `test_mode = false`로 내리고, 시작 화면 F3로 켠다(개발 빌드만). 저장 항목 없음.
- **이유:** 켜 둔 채 잊고 플레이해 기록·통계가 오염될 일이 없고 `user://` 저장도 필요 없다. 불편은 F5마다 F3 한 번.
- **다른 후보:** `settings.json`에 켠 상태 저장(편하지만 켜진 줄 모르고 플레이할 위험, 새 저장 키).
- **클래스 기본값은 true로 유지:** 기본값을 false로 바꾸면 COIN에 의존하는 기존 검사(state_test `insert_coin` 20곳, view_test 약 30곳)가 줄줄이 깨진다. 트리 밖에서 만드는 테스트용 인스턴스는 기본값(켜짐) 그대로 두고, 게임이 켜질 때(`_ready`)만 내린다. `view_test`는 시작 부분에 `GameState.test_mode = true` 한 줄을 넣었다(오토로드 `_ready`가 내리므로).

## 2. 미리보기는 별도 인스턴스 (main의 오버레이·정산 연출은 쓰지 않음)
- **선택:** `TestMenu`가 `FeverOverlay`·`SettleShow`·`GameOverOverlay`를 따로 만들어 가짜 값으로 재생한다. 정산 미리보기의 숫자는 메뉴 자체 라벨에 보인다.
- **이유:** main의 오버레이는 정산 핸들러와 이어져 있어(`_on_fever_finished` 등) 재생하면 실제 크레딧·표시가 움직이거나 `_last_result` 없이 오류가 난다. 별도 인스턴스는 게임 상태·WIN/CREDIT 칸을 전혀 바꾸지 않는다(view_test가 전후 비교).

## 3. 상태 설정은 기존 입구 + 새 입구 최소화
- **선택:** 크레딧은 기존 `grant_credit(test_coin)` 그대로, 피버 카운터·풀만 `SlotLogic`에 `set_fever_count`·`set_pool`을 새로 두고 `GameState` 래퍼(개발 빌드 + 테스트 모드 + 릴 정지 중만)로 감쌌다. 쓰면 `run_tainted`.
- **평균 베팅 합:** `(초기 − 설정값) × max(현재 BET, 피버 최소 베팅)`으로 채워 보너스가 0에 가깝게 나오지 않게 했다.

## 4. 결과 강제(C1)는 최소형으로 넣는다
- **필요성:** 세븐 라인 당첨은 1/3,277이라 카운터·풀을 설정해도 세븐 피버 + 풀 획득의 실제 흐름을 볼 수 없다(체리 1/8, 포도 1/106, 벨 1/243은 AUTO로 가능).
- **선택:** `SlotLogic.spin(bet, forced_stops = [])`. 지정값이 있어도 `roll_stops()`를 먼저 호출해 RNG를 소비하고 결과만 바꿔치기한다. 예약은 심볼만 저장하고 **START 순간의 베팅**으로 정지 위치를 찾으며(`find_stops_with_win`), 1회용이고 개발 빌드 + 테스트 모드가 아니면 비어 있는 목록만 들어간다.
- **원칙과의 관계:** 결과는 여전히 START 순간에 정해지고 화면은 보여주기만 한다. 강제한 판은 `run_tainted`로 기록에서 제외되고, 강제 판 뒤의 시드 순서는 변하지 않는다(state_test에서 100판 비교).
- **다른 후보:** 강제를 넣지 않기(세븐·풀 실제 흐름은 확인 불가), 정지 위치 직접 지정(밸런스 수치를 아는 사용자만 쓸 수 있음).

## 5. 메뉴는 판이 쉬는 중에만 열고 모달로 처리
- 릴·AUTO·정산 연출·피버/풀 오버레이·GAME OVER(대기 포함) 중에는 열지 않는다(8-A 설정과 같은 기준). 열려 있는 동안 키는 메뉴만 받고(`main._unhandled_key_input` 맨 위 한 곳), 마우스는 y 0~414 바탕이 막는다. 멈출 타이머가 없어 일시정지 처리가 필요 없다.
- 메뉴 노드는 GAME OVER 오버레이보다 아래에 둔다(기존 규칙 "GAME OVER 화면이 가장 위"를 지키고, 메뉴는 GAME OVER 중에 열 수 없음).
