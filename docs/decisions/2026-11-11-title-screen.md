# 시작 화면 (7-C)

## 1. 별도 title 씬에서 main 씬으로 전환
- **선택:** `title.tscn`을 메인 씬으로 하고, START 뒤 `change_scene_to_file("main.tscn")`로 넘어간다.
- **이유:** 시작 화면이 떠 있는 동안 main이 없으니 BGM·전구·타이머·입력을 따로 멈출 필요가 없다. 헤드리스 테스트가 `main.tscn`을 직접 만드는 7곳(view_test 4, match_test 1, 미리보기 2)은 변경 없이 그대로 통과한다.
- **다른 후보:** main 안 오버레이(GAME OVER 방식). main이 먼저 만들어져 BGM이 이미 돌고, 테스트 7곳과 view_test의 입력 경로가 모두 영향을 받는다.

## 2. 시작 크레딧은 START에서만 지급 (`GameState._ready()`의 `new_game()` 제거)
- **선택:** 오토로드는 `initialize()`만 하고 크레딧 0으로 대기한다. 시작 크레딧은 시작 화면 START가 부르는 `new_game()`이 `grant_credit(start)`로 한 번만 준다.
- **이유:** `_ready` 한 번 + START 한 번으로 3,000이 두 번 지급될 구조를 처음부터 없앤다. 테스트는 모두 `initialize()`로 시작해서 영향이 없었다.
- **다른 후보:** `_ready` 호출을 남기고 START에서 다시 `new_game()`. 덮어쓰기라 누적은 안 되지만 같은 일을 두 번 하는 구조라 채택하지 않았다.
- **참고:** `main.tscn`만 F6으로 실행하면 크레딧 0으로 뜬다. GAME OVER는 정산에서 0이 될 때만 켜지므로 뜨지 않는다(테스트로 확인).

## 3. START 중복 입력 방어와 소리 보호
- **선택:** START가 받아들여지면 `_starting` 플래그를 켜고 이후 모든 입력(START·EXIT·키)을 무시한다. `new_game()`은 그 순간 한 번만 부르고, 씬 전환은 `button.wav`의 재생 길이(스트림에서 읽음)만큼 기다린 뒤에 한다. 새 키 없음.
- **이유:** 전환 때문에 소리가 잘리지 않고, 연타해도 새 게임이 두 번 시작되지 않는다. EXIT는 확인 없이 바로 종료(Esc 포함)라 소리를 기다리지 않는다.

## 4. 로고는 기존 로고 ×2
- **선택:** 기존 `logo.png`(180×72)를 정수 2배(360×144, Nearest)로 표시. 새 큰 로고 그림은 만들지 않았다(생성기의 7c 코드도 제거, 미리보기 `assets/_preview/7c_*.png`만 남김).
- **다른 후보:** 큰 로고를 새로 찍기. 점 크기가 달라 보이는 문제를 피하는 장점이 있었으나 사용자가 ×2안을 선택했다.
