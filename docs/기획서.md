# FruitSlot 기획서

> 버전 0.1 (초안) · 작성 기준: 90년대 오락실 8라인 과일 슬롯
> 표시 **[임시]**는 시뮬레이션 후 조정할 수치. 최종 수치는 `data/balance.json`이 기준.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 가제 | FruitSlot |
| 장르 | 3×3 릴, 8라인 클래식 과일 슬롯 |
| 플랫폼 | PC (Windows), 추후 웹 내보내기 고려 |
| 해상도 | 640×480 (4:3) 기본, 정수배 확대 |

| 재화 | 크레딧(게임 내 점수). **현금·결제·환전 없음** |

## 2. 화면 구성

```
┌───────────────────────────────────────────┬──────────────┐
│  [라인 표시: 각 라인 끝에 라벨 + 베팅 수]    │  타이틀 로고  │
│                                           ├──────────────┤
│        ┌──────┬──────┬──────┐             │  POOL  0000  │
│        │ 릴1  │ 릴2  │ 릴3  │  (윗줄)     ├──────────────┤
│        ├──────┼──────┼──────┤             │ 피버 카운터   │
│        │      │      │      │  (가운데)   │ 체리  ×5     │
│        ├──────┼──────┼──────┤             │ 포도  ×9     │
│        │      │      │      │  (아랫줄)   │ 벨    ×7     │
│        └──────┴──────┴──────┘             │ 세븐  ×1     │
│          [STOP]  [STOP]  [STOP]           ├──────────────┤
│                                           │ 배당표(족보)  │
│                                           │ ■■■ → ×10    │
│                                           │ (심볼 7줄)    │
├──────────┬──────────────────┬─────────────┼──────────────┤
│ CREDIT   │ 안내 문구         │ WIN         │ BET          │
└──────────┴──────────────────┴─────────────┴──────────────┘
버튼: [CANCEL] [COIN] [START] [BET] [MAX BET] / [STOP1] [STOP2] [STOP3] [AUTO]
```

- 릴 영역: 3×3. 9칸의 테두리는 고정이고, 각 칸은 자기 칸 모양으로 잘라 보여 주는 창이다. 회전 중에는 그 안에서 심볼 두 개가 반쪽씩 걸쳐 스크롤하며, 심볼은 칸 밖으로 나가지 않는다. 릴마다 출발 시간차·속도차를 둔다(`data/feel.json`).
- 라인 라벨 A~H: 각 라인의 시작/끝 위치에 표시하고, 옆에 그 라인의 베팅 수를 숫자로 보여준다. 베팅이 0인 라인은 어둡게.
- 하단 안내 문구: "BET 8 이상이면 피버 적립" 같은 안내, 당첨 시 당첨 내용.
- 당첨 시 해당 라인을 선으로 그어 깜빡이고, 당첨 심볼을 강조한다.
- **배당표(족보)**: 오른쪽 패널 피버 카운터 아래에 심볼 7줄을 작게 보여준다. 줄마다 심볼 이름, 화면과 같은 색의 작은 박스 3개, 배수(×N)를 표시한다. 배수는 "그 라인의 베팅"에 곱해지는 값이라 제목에 "3개 일치 × 라인 베팅"이라고 적는다. 숫자는 `balance.json`의 배당표에서 읽는다.
- **버튼 줄**: CANCEL / COIN / START / BET / MAX BET. 할 수 없는 상태(크레딧 0, 이미 BET 0 등)면 비활성으로 표시한다.
- **AUTO 버튼**: STOP 3 오른쪽(오른쪽 패널 왼쪽)에 둔다. 켜지면 밝은 금색(ON) 모양으로 바뀐다. 규칙은 6장 "AUTO".

## 4. 라인 (8라인)

3×3 칸을 (열, 행)으로 표기. 열 0~2(왼→오), 행 0~2(위→아래).

| 라인 | 종류 | 칸 |
|---|---|---|
| A | 가로 가운데 | (0,1) (1,1) (2,1) |
| B | 가로 윗줄 | (0,0) (1,0) (2,0) |
| C | 가로 아랫줄 | (0,2) (1,2) (2,2) |
| D | 대각선 ↘ | (0,0) (1,1) (2,2) |
| E | 대각선 ↗ | (0,2) (1,1) (2,0) |
| F | 세로 왼쪽 | (0,0) (0,1) (0,2) |
| G | 세로 가운데 | (1,0) (1,1) (1,2) |
| H | 세로 오른쪽 | (2,0) (2,1) (2,2) |

- 라인 데이터는 `balance.json`에 칸 좌표 배열로 저장한다.
- **세로 라인 주의:** 세로 당첨은 한 릴에 같은 심볼이 3칸 연속으로 보일 때만 나온다. 따라서 세로 당첨 확률은 릴 스트립의 "같은 심볼 연속 배치"로 조절한다.

## 5. 베팅

- **BET 버튼을 누를 때마다 베팅이 1씩 늘고, 라인 A→H 순서로 1씩 배분**된다. 9번째부터는 다시 A부터 2씩.
  - 예: BET 1 → A에 1 / BET 3 → A,B,C에 1씩 / BET 8 → 8라인 모두 1 / BET 16 → 모두 2
- 최대 베팅: 64 (라인당 8) **[임시]**
- **MAX BET**: 누르면 베팅을 min(최대 베팅, 현재 크레딧)으로 한 번에 맞춘다. 라인 배분은 BET과 같은 A→H 순서.
- **CANCEL**: 누르면 베팅을 0으로 되돌린다. 크레딧은 START 때 차감되므로 변하지 않는다.
- 크레딧이 0이거나 이미 같은 상태면(베팅이 이미 MAX BET 목표값, 또는 이미 0) 해당 버튼은 비활성.
- **크레딧은 START를 누르는 순간 베팅만큼 차감**된다. BET 버튼은 크레딧을 차감하지 않는다.
- BET은 **새 베팅이 현재 크레딧 이하일 때만** 늘어난다. 크레딧이 모자라면 늘지 않고 안내한다. 최대 베팅에서 한 번 더 누르면 1로 돌아간다.
- 시작 크레딧은 0이다. COIN을 눌러야 베팅할 수 있다.
- 스핀이 끝나면 베팅은 직전 값을 유지한다(같은 베팅으로 바로 START 가능).
- **스핀 후 크레딧이 직전 베팅보다 적어지면 베팅을 크레딧만큼 자동으로 낮추고** 안내 문구로 알린다. 크레딧이 0이면 베팅도 0이다.
- **BET 8 이상(모든 라인 활성)일 때만 피버 적립과 풀 획득이 가능**하다. 화면에 항상 안내한다.

## 6. 진행 흐름

1. **COIN**: 크레딧 +100 (무료, 횟수 제한 없음)
2. **BET**: 베팅 설정
3. **START**: 크레딧에서 베팅 차감 → **이 순간 RNG로 3개 릴의 정지 위치를 결정** → 릴 회전 시작
4. **STOP 1/2/3**: 각 릴을 멈춘다. 순서 자유. 누르지 않으면 회전 시작 후 일정 시간이 지나 자동으로 왼쪽부터 정지 **[임시: 3초 후 0.4초 간격]**
   - STOP은 "멈추는 타이밍 연출"일 뿐 결과는 이미 정해져 있다.
   - 버튼을 누른 순간부터 미리 정해진 위치에 자연스럽게 감속해 멈춘다(짧은 미끄러짐 연출).
   - 결과가 정해져 있으므로 STOP 후 멈추기까지의 대기는 그때그때 다르다(최대 한 바퀴 + 감속).
   - 회전 중 START(스페이스/엔터)를 누르면 아직 멈추지 않은 릴이 왼쪽부터 차례로 멈춘다. START 직후 짧은 시간은 무시한다.
   - 회전 중에는 COIN / BET / MAX BET / CANCEL을 쓸 수 없다.
   - 회전·감속·튕김·자동 정지 시간 등 손맛 수치는 `data/feel.json`이 기준이다(`docs/feel.md` 참고).
5. 세 릴이 모두 멈추고 짧은 간격 뒤 당첨 판정 → 당첨 라인 연출 → WIN 표시 → 크레딧에 합산(크레딧은 START 때 베팅만큼 줄고, 당첨금은 이때 한 번에 더해진다)
   - WIN은 라인 당첨 + 피버 보너스 + 풀의 **총합**이다. 안내 문구에 "라인 X + 피버 Y + 풀 Z" 내역을 함께 보여준다.
6. 피버 카운터·풀 갱신 → 다음 스핀 대기

### AUTO (자동 스핀)

- **AUTO 버튼(또는 A 키)** 으로 켜고 끈다. 켜면 **현재 BET을 유지한 채**, 한 판이 정산된 뒤(피버·풀 연출이 있으면 그것까지 끝난 뒤) 대기시간 뒤에 **다음 판을 자동으로 시작**한다. 대기시간은 `feel.json`의 `auto_spin_gap_sec`(기본 0.5초)이고 다음 스핀부터 적용된다.
- AUTO는 "다음 판을 자동으로 시작"할 뿐이다. 결과(RNG)나 확률에는 관여하지 않는다. 릴 정지는 기존 자동 정지 시간표를 그대로 쓴다.
- 쉬는 중에 켜면 바로 첫 판을 시작하고, 회전 중에 켜면 그 판이 정산된 뒤부터 이어진다.
- **AUTO 중 비활성**: BET / MAX BET / CANCEL / STOP 1~3 (키보드 B, M, X, 1, 2, 3도 무시). COIN은 허용한다.
- **끄기**: AUTO 버튼을 다시 누르거나(A 키), 정산 뒤 대기시간 중에 START를 누른다. **진행 중인 판은 끊지 않고 끝까지 진행**하고 다음 판만 시작하지 않는다. 회전 중·피버 연출 중의 START는 기존 역할(남은 릴 정지 / 연출 건너뛰기)만 하고 AUTO를 끄지 않는다.
- **자동으로 꺼지는 경우**: ① 정산 뒤 크레딧이 총 BET보다 적을 때(이어서 5장의 베팅 자동 하향이 적용된다), ② 한 판 WIN(라인 + 피버 + 풀)이 `balance.json`의 `auto_spin.stop_on_win_at` 이상일 때(0 = 사용 안 함, 기본 0).
- 켤 수 있는 조건: BET이 1 이상이고(쉬는 중이면) 크레딧 이내일 때. 아니면 AUTO 버튼은 비활성이다.
- **안내 문구**: AUTO 중에는 첫 줄에 "AUTO N회"(N = AUTO를 켠 뒤 시작한 판 수)를 고정하고, 그 아래에 기존 문구(당첨 내역 등)를 보여준다. AUTO 중에는 "BET 8 이상이면 피버 적립" 줄을 생략한다. AUTO가 꺼진 이유는 일회성 문구로 알린다(결과 문구 뒤).

## 7. 당첨 판정과 배당

- 활성 라인(베팅 1 이상)에서 **같은 심볼 3개**면 당첨.
- 당첨금 = 배당 배수 × 그 라인의 베팅 수
- 여러 라인이 동시에 당첨되면 전부 합산.

| 심볼 | 3개 배당 (× 라인 베팅) |
|---|---|
| 체리 | 10 **[임시]** |
| 오렌지 | 15 **[임시]** |
| 수박 | 30 |
| 포도 | 35 |
| 벨 | 50 **[임시]** |
| BAR | 100 **[임시]** |
| 세븐 | 200 **[임시]** |

- 1차 버전은 "3개 일치"만. 체리 1~2개 소액 지급, 와일드 등은 확장 항목으로 둔다(11장).

## 8. 피버 (누적 보너스)

- 대상 심볼과 초기 카운트, 보너스 배수는 **`data/balance.json`이 기준**이다(밸런스 조정으로 아래 [임시] 값과 달라졌다. 현재 값(v0.3): 체리 24, 포도 4, 벨 3, 세븐 1 / 배수 14, 30, 50, 100).
- 처음 설계 값 **[임시]**: 체리 5, 포도 9, 벨 7, 세븐 1
- **BET 8 이상**으로 스핀해서 대상 심볼 3개 당첨이 나오면 그 심볼의 카운터가 1 줄어든다(한 스핀에 여러 라인으로 당첨돼도 1만 줄어든다 **[임시]**).
- 카운터가 0이 되면 **피버 발동**:
  - 피버 보너스 = 피버 배수 × **카운터를 줄인 판들의 평균 베팅**(소수점 버림). 처음 설계 배수 **[임시: 체리 20, 포도 40, 벨 30, 세븐 100]**
    - 계산: 배수 × (그 심볼의 카운터를 줄인 판들의 총 베팅 합 ÷ 초기 카운트). 예: 체리(카운트 24, 배수 14)를 BET 8로 23번, 마지막에 BET 64로 1번 줄였다면 14 × (248 ÷ 24) = 144 (발동한 판의 베팅 64 기준인 896이 아니다).
    - 같은 베팅으로만 쳤다면 "배수 × 그 베팅"과 같다. 세븐처럼 카운트가 1인 심볼은 발동한 판의 베팅이 곧 평균이다.
    - 이유: 발동한 판의 베팅만 보면, 낮은 베팅으로 카운터를 줄이다가 마지막 1회(깜빡일 때)만 베팅을 올리는 방법으로 RTP가 100%를 넘는다(7-A 조사: 약 128%).
    - 베팅 합은 발동하면 0부터 다시 쌓인다. BET 8 미만의 판은 카운터도 베팅 합도 건드리지 않는다.
    - 기준은 `balance.json`의 `fever.bonus_bet_basis`(`"average"` = 평균 베팅(기본), `"trigger"` = 발동한 판의 베팅). 다른 값이면 기본값으로 대체한다.
  - 오버레이 연출(사운드는 6단계): 화면 윗부분(하단 CREDIT·WIN·BET 표시창 줄 위까지)을 덮고, 표시창 줄은 연출 중에도 그대로 보인다(마우스·키 입력 차단은 화면 전체). "FEVER!" 배너, 심볼 칸 그림, 심볼 이름, "BONUS +금액"을 표시. 한 스핀에 피버가 둘 이상이면 체리 → 포도 → 벨 → 세븐 순서로 심볼별로 차례로 보여 준다(별도 BONUS 칸 없음, 오버레이 가운데에 표시).
  - 오버레이 동안 COIN/BET/MAX BET/CANCEL/STOP은 잠기고, 스페이스(START)는 연출 건너뛰기다. 건너뛰어도 결과와 숫자는 같다. 시간은 `data/feel.json`(`fever_overlay_sec` 등).
  - 카운터는 오버레이가 뜰 때 해당 심볼이 0으로 보이고, 그 심볼의 단계가 끝나면 초기값으로 돌아간다. CREDIT·WIN·POOL과 "라인 X + 피버 Y + 풀 Z" 안내는 오버레이가 모두 끝난 뒤 한 번에 갱신한다. 당첨 선은 오버레이 전에 먼저 켠다.
  - 세븐 피버로 풀을 획득하면 세븐 단계 바로 뒤에 "POOL GET!" 단계가 이어진다(9장). 건너뛰기·잠금·정산 시점 규칙은 피버 단계와 같다.
  - 피버 보너스는 크레딧에 합산
  - 카운터는 초기값으로 리셋
- 카운터 진행 상황은 오른쪽 패널에 항상 보인다. 심볼마다 색 박스 + 이름 + ×남은 횟수 한 줄이다.
- 초기값이 2 이상인 심볼이 **마지막 1회**만 남으면 그 줄이 깜빡인다(세븐처럼 처음부터 1인 심볼은 제외).

## 9. 풀 (누적 잭팟)

- 적립률·초기값 등 풀 수치는 **`data/balance.json`이 기준**이다(현재(v0.3) 적립률 6%, 초기값 250).
- 매 스핀 베팅액의 **6%**(처음 설계 5%)가 풀에 적립된다(지급 재원과 별개로 표시용 누적값). 풀베팅 8이면 스핀당 0.48(내부에서 소수점까지 누적, 표시는 정수 버림).
- 풀은 표시용 누적값이므로 적립은 RTP에서 빼지 않고, **획득액은 전액 RTP에 포함**된다. 풀 RTP = 적립률 + 초기값 ÷ (획득 간격 × BET).
- 풀 초기값 **250**(처음 설계 500), 획득 후 이 값으로 리셋.
- **획득 조건:** BET 8 이상에서 세븐 피버가 발동하면 풀 전액을 함께 획득 **[임시]**.
- **풀 획득 연출:** 세븐 피버 단계가 끝나면 "POOL GET!" 배너와 "POOL +금액" 단계를 보여 준다(심볼 이름 줄은 없음). 시간은 `data/feel.json`의 `pool_overlay_sec`(기본 3초). 이 단계가 끝나면 오른쪽 패널의 POOL이 초기값으로 돌아가고, CREDIT·WIN·"라인 X + 피버 Y + 풀 Z" 안내는 연출이 모두 끝난 뒤 한 번에 갱신한다. 건너뛰어도 금액은 같다.
- 풀 금액은 오른쪽 패널에 항상 표시하고, 커질수록 숫자 색을 바꿔 기대감을 준다: 기본 주황 → 1,000 이상 노랑 → 1,500 이상 빨강(가볍게 깜빡임). 기준 숫자는 `data/feel.json`(`pool_yellow_from`, `pool_red_from`)에서 조정한다.

## 10. 밸런스 목표와 릴 스트립

| 항목 | 목표 **[임시]** |
|---|---|
| RTP (피버·풀 포함) | 92~95% |
| 히트 빈도 (풀베팅, 1개 라인 이상 당첨) | 25~35% |
| 피버 발동 | 평균 100~300 스핀에 1회 |
| 풀 획득 | 평균 2,000~5,000 스핀에 1회 |

- **판정 기준(7-A):** 목표는 BET 8~64에 적용한다(BET 1~7은 피버·풀이 없어 RTP 약 64~71%, 의도된 값). 합격 판정은 **이론값(릴 정지 조합 32,768가지 전수 계산)** 으로 한다. 시뮬레이션은 세븐 피버·풀 한 방의 비중이 커서 10만 회로도 RTP가 약 ±1.9%p 흔들리므로 교차 확인용이다.
- **현재 이론값(v0.3):** RTP는 BET 8 = 93.69% / 16 = 93.21% / 64 = 92.85%, 히트 빈도 28.90%, 피버 106.1 스핀에 1회(체리 185.9 / 포도 422.8 / 벨 728.2 / 세븐 3,276.8), 풀 3,276.8 스핀에 1회. `scenes/test/sim.tscn`이 이 값과 목표 충족 여부를 출력한다.
- **확인 필요:** 라인마다 베팅이 고르지 않은 BET(8의 배수가 아닌 값) 중 10~14, 21은 가로·대각 라인에 베팅이 더 실려 RTP가 95%를 넘는다(최고 BET 13 = 96.86%). 세로 라인(오렌지만 당첨)의 RTP가 가로·대각보다 낮아서 생기는 구조이며, 처리 방향은 미정이다.
- 각 릴은 32칸짜리 스트립(심볼 순서 배열). 릴마다 구성이 달라도 된다.
- 초기 구성 예시 (릴당 32칸) **[임시]**: 체리 8, 오렌지 7, 수박 6, 포도 5, 벨 3, BAR 2, 세븐 1
- 현재 구성(v0.2부터, `balance.json`이 기준): 릴 1 = 체리 9, 오렌지 8, 수박 4, 포도 4, 벨 3, BAR 2, 세븐 2 / 릴 2·3 = 체리 10, 오렌지 8, 수박 4, 포도 4, 벨 3, BAR 2, 세븐 1. 세로 당첨은 세 릴 모두 오렌지 3연속 1곳뿐이다.
- 세로 라인 확률을 위해 일부 심볼을 2~3칸 연속으로 배치한다.
- **수치 조정 순서:** 엑셀로 대략 계산 → `balance.json` 반영 → 시뮬레이션 100,000회로 검증 → 목표 범위에 들어올 때까지 반복.

## 11. 확장 항목 (1차 버전 이후)

- 체리 1~2개 소액 지급
- 더블업(당첨금 걸고 홀짝/하이로우)
- 와일드 심볼
- 크레딧 저장/불러오기, 최고 기록
- 그래픽·사운드 교체, 타이틀 화면, 데모(어트랙트) 모드
- 웹 내보내기
- **운영자 설정 화면** — 밸런스·손맛 수치를 게임 안에서 조정 (12장 8단계). 변경은 다음 스핀부터 적용되고, 진행 중인 스핀의 결과는 절대 바뀌지 않는다.

## 12. 개발 단계

각 단계는 완료 조건을 만족하고 사용자 확인을 받은 뒤 다음으로 넘어간다.

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| 1 | **데이터와 로직** — `balance.json`, SlotLogic(정지 위치 결정, 3×3 결과, 라인 판정, 배당, 피버, 풀), 시뮬레이션 씬 | 시뮬레이션 10만 회 실행 시 에러 0, RTP 등 통계 출력 |
| 2 | **정지 화면** — 3×3 결과를 색 박스로 표시, START 한 번에 결과 바로 표시 | 화면 결과가 로직 결과와 일치 (사용자 확인) |
| 3 | **베팅·라인 UI** — COIN/BET, 라인 라벨과 베팅 수, 당첨 라인 강조, CREDIT/WIN 표시 | 베팅 배분·차감·합산이 기획서대로 동작 |
| 4 | **릴 회전과 STOP** — 회전 애니메이션, STOP 1/2/3, 자동 정지, 감속 연출 | 손맛 확인 (사용자 확인) |
| 5 | **피버·풀** — 카운터 패널, 피버 연출, 풀 표시와 획득 | 시뮬레이션 수치와 실제 플레이 일치 |
| 6 | **연출·사운드·그래픽** — 효과음, 당첨 연출, 심볼 그림 교체 | 사용자 만족 |
| 7 | **밸런스 마감** — 목표 범위 맞추기, 버그 수정 | 10장 목표 충족 |
| 8 | **운영자 설정** — 밸런스(`balance.json`)·손맛(`feel.json`) 수치를 게임 안의 화면에서 조정. 변경은 **다음 스핀부터** 적용하고, 진행 중인 스핀의 결과·연출은 **절대 바뀌지 않는다**(결과는 START 때 RNG로 한 번 확정한다는 규칙 유지) | 화면에서 바꾼 값이 다음 스핀부터 반영되고 진행 중 스핀은 불변 (자동 테스트 + 사용자 확인) |
