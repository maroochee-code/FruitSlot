## 5단계 · 5-B — 피버 발동 연출 (v0.6.0, 2026-11-09 · 사용자 확인 대기)

`scripts/logic/`·`balance.json`·`project.godot` 변경 없음. (도중에 작업이 중단돼 파일 상태를 확인한 뒤 이어서 완성함)

### 완료한 내용
- `FeverOverlay`: "FEVER!" / 심볼 이름(심볼 색 배너) / "BONUS +금액", 단계 사이 간격, 우측 위 "1 / 2" 표시, 아래 "SPACE: 건너뛰기"
- 순서: balance.json 피버 대상 순서(체리, 포도, 벨, 세븐). 세븐 뒤 풀 획득 단계 자리는 `build_steps`에 비워 둠 (5-C)
- 정산 시점: 피버가 있으면 `settle_spin`을 오버레이가 끝난 뒤에 호출 → CREDIT·WIN·POOL·카운터 리셋·"라인 X + 피버 Y + 풀 Z" 안내가 한 번에 바뀜. 연출 중 `GameState.spinning`이 유지되어 COIN/BET/MAX BET/CANCEL/STOP은 기존 잠금 그대로 막힘
- 건너뛰기: 스페이스 또는 START. 뜬 직후 `fever_skip_lock_sec`(0.4초)는 무시. 건너뛰어도 정산 경로가 같아 숫자 동일
- 카운터: 오버레이가 뜨면 발동한 심볼 0, 그 단계가 끝나면 초기값
- feel.json 새 키(범위): `fever_overlay_sec` 2.0 (0.2~10), `fever_step_gap` 0.3 (0~5), `fever_skip_lock_sec` 0.4 (0~5). 이번 스핀 시작 때의 설정으로 재생 → 도중에 파일을 고쳐도 이번 연출 불변

### 검증
- 판정 44/44, 상태 56/56, 릴 68/68, 화면 169/169 통과. 메인 씬 `run_project` 에러·경고 0
- 피버 전용 시험(피버 초기값을 전부 1로 낮춘 시험용 데이터, 같은 시드): 2개 동시 발동 스핀과 1개 스핀을 끝까지 재생하며 매 프레임 확인 — 단계 순서·글자·금액, 카운터 0→초기값, 정산 전 크레딧/WIN 불변, 잠금(C/B/M/X/STOP), 재생 시간 = 단계×시간+간격(도중 feel.json 변경에도 불변), 정산 후 크레딧/WIN/안내/POOL
- 같은 스핀을 스페이스로 건너뛴 결과 CREDIT·WIN·BET·POOL·카운터·안내가 자연 재생과 완전히 같음
- 일부러 망가뜨려 확인: 오버레이 시작과 동시에 정산 / 단계 순서 뒤집기 / 건너뛰기 잠금 무시 → 모두 검사가 실패함을 확인 후 원복

### 가정
1. 당첨 선·테두리는 릴이 멈춘 직후(오버레이 전)에 켠다. 정산 때가 아님
2. 오버레이 중 START 버튼은 켜짐(건너뛰기용). 오버레이가 화면을 덮어 마우스로는 못 누르고 스페이스/엔터로 건너뜀
3. 건너뛰기 잠금 `fever_skip_lock_sec`는 요청에 없던 세 번째 키 (연타 방지용)
4. 오버레이 글자·색·배치는 `fever_overlay.gd` 상수 (눈으로 확인 후 조정)
5. 사운드·당첨금 카운트업은 6단계

### 눈으로 확인할 것
FEVER! 글자 크기·깜빡임, 심볼 배너, BONUS 숫자 위치, 단계 사이 간격, 건너뛰기 느낌, 오버레이 뒤로 비치는 화면 밝기

### 확인 방법 (F5) — 피버를 빨리 보기
1. 임시로 `data/balance.json`의 `fever.targets`에서 CHERRY `initial_count`를 20 → 1로 고친다 (확인 후 20으로 되돌리기)
2. F5 → `C`(COIN) → `M`(MAX BET) → 스페이스를 반복. 체리 3개 당첨이 나오면 곧바로 피버 (평균 몇 판)
3. 오버레이 동안: 안내 문구 "피버 발동!…", CREDIT·WIN·POOL이 그대로인지, 카운터 체리가 ×0인지, C/B/M/X/1·2·3이 안 먹는지
4. 오버레이 끝나면 CREDIT·WIN이 한 번에 바뀌고 안내에 "라인 X + 피버 Y + 풀 Z"가 뜨고 체리 카운터가 ×1(초기값)로 돌아오는지
5. 건너뛰기: 오버레이가 뜬 뒤 0.4초가 지나 스페이스 → 즉시 끝나고 숫자는 같음
6. 둘 이상 동시: CHERRY, GRAPE, BELL을 모두 1로 낮추면 가끔 연달아 나옴 (체리→포도→벨 순서)
7. 시간 조절: 켜 둔 채 `feel.json`의 `fever_overlay_sec`을 4로 저장 → 다음 스핀부터

## 5단계 · 5-A — 피버 카운터 패널과 POOL 색 단계 (v0.5.0, 2026-11-09 · 사용자 확인 대기)

5단계를 5-A(패널·풀 표시) / 5-B(피버 발동 연출) / 5-C(풀 획득 연출 + 화면=로직 자동 비교)로 나눠 진행. 이번은 5-A뿐이다. `scripts/logic/`·`balance.json`·`project.godot` 변경 없음.

### 완료한 내용
- `FeverPanel`: 피버 카운터를 심볼별 한 줄(색 박스 + 이름 + ×남은 횟수)로 표시. 숫자는 `balance.json`에서만 읽음 (체리 20, 포도 4, 벨 3, 세븐 1)
- 마지막 1회 깜빡임: **초기값 2 이상**인 심볼에만 적용 (체리·포도·벨). 세븐은 처음부터 1이라 제외
- POOL 색 3단계: 1,000 미만 주황 / 1,000 이상 노랑 / 1,500 이상 빨강+깜빡임. 기준은 `feel.json`의 `pool_yellow_from`, `pool_red_from` (노랑 ≥ 빨강이면 둘 다 기본값으로 대체)
- 숫자·색은 정산 시점(릴이 다 멈춘 뒤)에 바뀜 — 기존 규칙 그대로

### 확인한 사실 (풀 적립률)
`balance.json`의 `contribution_rate` = 0.05 → 풀베팅 8 × 5% = **0.4/스핀**. 기획서 9장(베팅의 5%)과 **같은 값**이라 적립률은 고치지 않았다. 대신 8·9장에 "수치는 balance.json이 기준"을 명시했다. 8장의 피버 초기값·배수가 balance.json과 달랐던 것(체리 5→20, 포도 9→4, 벨 7→3, 배수 20/40/30→11/30/50)도 같은 방식으로 정리 (**확인 필요**: 8장까지 고친 것은 "balance.json이 기준" 취지로 판단한 것)

### 검증
- 판정 44/44, 상태 56/56, 릴 65/65, 화면 118/118 통과. 메인 씬 `run_project` 에러·경고 0
- 신규 검사: 카운터 숫자=balance.json, 마지막 1회 깜빡임(세븐 제외), 풀 색 경계값, 빨강 단계 깜빡임, feel.json 기준 읽기·잘못된 값 대체
- 일부러 망가뜨려 확인: 세븐도 깜빡이게 / 노랑 기준 경계 오류 → 해당 검사가 실패함을 확인 후 원복

### 가정
1. 빨강 단계의 "가벼운 깜빡임"은 빨강 ↔ 어두운 빨강, 주기 0.8초 (`main.gd` `BLINK_PERIOD`, 화면 상수)
2. 풀 색 기준은 다른 feel 값처럼 **다음 스핀부터** 적용
3. 깜빡이는 줄은 이름·숫자가 빨강으로 바뀌는 방식

### 눈으로 확인할 것
- 오른쪽 패널의 피버 카운터 줄 배치(색 박스·이름·숫자)가 보기 좋은지
- 깜빡임 속도·강도, POOL 색 구분

### 확인 방법 (F5)
1. F5 → 오른쪽 위 POOL 아래 피버 카운터가 4줄(체리 ×20, 포도 ×4, 벨 ×3, 세븐 ×1)로 보이는지
2. 색 단계 확인: `data/feel.json`의 `pool_yellow_from`을 400, `pool_red_from`을 600으로 저장 → `C`, `M`, 스페이스로 한 판 돌리면 POOL(약 500)이 노랑이 됨. 더 낮게(예: 300/450) 하면 빨강+깜빡임. 확인 후 1000/1500으로 되돌리기
3. 마지막 1회 깜빡임은 포도·벨이 3~4번 당첨돼야 보임(오래 걸림). 빨리 보려면 `balance.json` 포도 `initial_count`를 2로 잠깐 낮춰 보기(확인 후 되돌리기)

## 5단계 선행 과제 — 릴 연출 방식 변경 (v0.4.1, 2026-11-09 · 사용자 확인 대기)

5단계(피버·풀 연출) 전에 릴의 모양을 바꿨다. 4단계의 "릴 창 전체가 한 덩어리로 흐르는" 방식을 칸 단위 클리핑 창으로 교체했다.
**연출만 바꿨고 `scripts/logic/`과 `data/balance.json`은 수정하지 않았다** (결과는 START 때 RNG로 한 번 확정 그대로). `project.godot` 변경 없음.

### 완료한 내용
| 항목 | 내용 |
|---|---|
| 칸 단위 클리핑 창 | 릴 3개 × 칸 창 3개 = 9칸이 고정. 창마다 `clip_contents`로 잘라 보여 주고, 안에서 위/아래 심볼 두 개가 반쪽씩 걸쳐 스크롤. 위아래 반 칸 덤 영역·어두운 가림막 삭제 (`reel_view.gd`, `main.gd`) |
| 창 테두리 | 고정 테두리 2px(`ReelView.WINDOW_FRAME_*`)를 창 위에 덧그려, 스크롤 중인 심볼의 테두리가 창 가장자리에서 흐르는 것을 가림 |
| 출발 시간차·속도차 | `feel.json`에 `reel_start_delay` [0, 0.08, 0.16]초, `reel_speed_scale` [1.0, 0.95, 1.05] 추가 (`half_row` 삭제). `FeelConfig`가 릴 3개짜리 목록을 읽고 검사 |
| 컨트롤러 | `SpinController`가 릴별 출발을 관리 (`reel_started` 신호, `has_started()`). 프레임 중간에 출발한 릴은 출발 순간부터의 시간만큼만 이동 |
| 문서 | `docs/feel.md`, `docs/기획서.md`(릴 영역 문구), `CHANGELOG.md`, 결정 기록 `docs/decisions/2026-11-09-reel-window-and-stagger.md`, 버그 기록 `docs/bugs/2026-11-09-stop-button-not-enabled-after-delay.md` |

### 검증
- 판정 44/44, 상태 56/56, 릴 61/61(기존 35 + 신규 26), 화면 94/94(기존 85 + 신규 9) 통과. 메인 씬 `run_project` 에러·경고 0
- **결과 불변**: 릴 움직임·컨트롤러 무작위 시험에서 출발 지연(0~0.5초)·속도 배율(0.5~1.5) 무작위 조합 포함, 최종 정지 위치 == 목표 정확히 일치. 화면 300회 스핀(입력 4가지)에서 최종 칸 9개 == 로직 grid
- 매 프레임 검사 추가: 보이는 심볼이 실제 스트립 순서, 창이 두 심볼로 빈틈·겹침 없이 채워짐 + clip 켜짐, **9칸 창의 위치·크기가 회전 중 불변**, 출발 시각 == 지연 시각, 출발 전 STOP 불가
- 검사가 헛돌지 않는지 확인: clip 끄기 / 아래 칸 위치 어긋내기 / 출발 지연 무시 / 속도 배율 무시로 일부러 망가뜨리면 해당 테스트가 실패함을 확인한 뒤 원복
- 개발 중 버그 1건 발견·수정: 지연 중인 릴의 STOP 버튼이 출발해도 안 켜짐 → `reel_started` 신호 (`docs/bugs/` 참고)

### 가정 / 사용자 승인 사항 (제안 1~5 승인 + 기본값 지정)
1. `half_row` 삭제, 기본값 `reel_speed_scale` [1.0, 0.95, 1.05] (사용자 지정), `reel_start_delay` [0, 0.08, 0.16]
2. 자동 정지는 START 기준 그대로. 출발 지연이 `auto_stop_start` 이상이면 지연을 기본값(그래도 안 맞으면 0)으로 대체하고 문제로 기록
3. 출발 전 릴은 STOP 버튼·키 불가(출발하면 켜짐). 회전 중 START는 출발 전 릴도 같은 순서로 예약해 출발 직후 정지
4. 창 안 두 심볼은 칸 사이 간격 없이 붙어 스크롤 (스크롤 한 칸 = 칸 높이 78px). 칸 높이는 78 그대로 (88로 되돌릴 수 있음: 릴이 y 55~327로 STOP 자리 340 위에서 끝남 — 원하시면 지시)
5. 세로 라인 라벨 F·G·H는 릴 위쪽(y 약 27~51)에 그대로 둠 — 덤 영역이 없어져 겹침 문제는 사라졌을 것 (눈으로 확인 필요)

### 눈으로 확인할 것
- 회전 중 9칸의 테두리가 고정돼 있고, 심볼이 칸 밖으로 번지거나 이웃 칸과 겹쳐 보이지 않는지
- 고정 테두리(회색 2px)가 심볼 고유 테두리를 가려 멈춘 모습이 4단계보다 밋밋해지지 않았는지 (두께·색은 `reel_view.gd` 상수)
- 릴이 왼쪽부터 차례로 출발하는 느낌과 속도차가 보이는지 (손맛은 `feel.json`으로 조절)
- 라인 라벨 F·G·H 위치

### 확인 방법 (F5)
1. F5 → `C` → `M` → 스페이스
2. 회전 중 9칸 테두리가 흔들리지 않고, 칸 안에서 위 심볼 아랫부분 + 아래 심볼 윗부분이 같이 흐르는지
3. 릴1→2→3 순서로 아주 조금씩 늦게 출발하고, 속도가 조금씩 다른지. 출발 직후 STOP 3 버튼이 잠깐 회색이다가 켜지는지
4. 게임을 켠 채 `data/feel.json`의 `reel_start_delay`를 `[0.0, 0.3, 0.5]`로, `reel_speed_scale`을 `[1.0, 0.7, 1.3]`으로 고쳐 저장 → 다음 스핀부터 시간차·속도차가 크게 보이는지 (되돌리려면 원래 값으로 저장)
5. 1·2·3 키, 회전 중 스페이스, 자동 정지가 전과 같이 동작하고 멈춘 뒤 WIN·크레딧이 갱신되는지

## 4단계 — 릴 회전과 STOP (v0.4.0, 2026-11-09 · 사용자 확인 대기)

### feel.json 실행 중 재로딩 (4단계에 포함)
- 파일 수정 시각을 0.5초마다 확인해 저장하면 자동으로 다시 읽고, **F6**은 즉시 다시 읽는다.

- 파일이 깨져 못 읽으면 이전 값 유지, 범위 밖 항목은 기본값 + 안내 문구(경고 로그 없음). `half_row`만 재시작 필요.

### 가정
1. 자동 정지 시각은 START 기준(3.0, 3.4, 3.8초). 먼저 손으로 멈춘 릴은 건너뛰고 나머지 시각은 그대로.
2. 회전 중 START: 남은 릴을 왼쪽부터 `quick_stop_interval`(0.15초) 간격으로 차례로 정지. START 직후 0.3초는 무시. 두 번째 누름은 무시.
3. 감속 구간은 항상 `slide_cells`(3칸)로 같고, STOP 후 멈추기까지 대기는 목표 위치에 따라 0~한 바퀴(약 1.2초)+0.5초.
4. 정산은 마지막 릴이 멈춘 뒤 `result_delay`(0.25초) 지나서. 그 사이에도 조작 잠금 유지.
5. 처음 화면의 릴은 스트립 0번 위치 심볼을 보여줌 (이전에는 빈 박스). 이 위치는 결과와 무관.
6. 칸 높이 78, 릴 y 55로 변경 (사용자 승인). 세로 라인 라벨(F·G·H)은 위쪽 덤 영역 위에 겹쳐 그려진다 (확인 필요).
7. 회전 중 안내 문구: "STOP 1·2·3 또는 START로 릴을 멈추세요."
8. 회전 중 START 버튼은 정지시킬 릴이 남아 있으면 활성 (이름은 START 그대로).
9. 당첨금 카운트업 등 연출은 6단계.

### 남은 문제 / 눈으로 확인할 것
- 손맛(회전 속도, 감속, 튕김, 대기 시간)은 사용자 확인 필요. 수치는 `data/feel.json`만 고치면 됨.
- 라인 라벨 F·G·H가 위쪽 덤 영역(어두운 막) 위에 겹쳐 읽기 괜찮은지 확인 필요.

### 사용자 확인 후 추가한 것 (같은 3단계에 포함)
- **MAX BET (M)**: 베팅 = min(최대 베팅, 현재 크레딧). 이미 그 값이면 비활성.
- **CANCEL (X)**: 베팅 0. 크레딧 변화 없음. 베팅이 이미 0이면 비활성.
- 버튼 줄: CANCEL / COIN / START / BET / MAX BET (버튼 폭 96→76, START 120→100, 글자 13).
- **배당표**: 피버 카운터 아래(y 260~416)에 7줄. 자리가 충분해 억지로 넣지 않았다. 제목에 "(3개 일치 × 라인 베팅)"을 적어 기준을 표시.
- 기획서 2·5·13장에 반영 (단축키 M, X 추가. 기존 C, B, 스페이스/엔터, 1/2/3, F1과 겹치지 않음).

### 검증
- 판정 테스트 44/44, 상태 테스트 50/50, 화면 테스트 40/40 (300회 스핀마다 칸·CREDIT·WIN·BET·POOL·피버·당첨 선 개수 일치, 배당표 숫자=balance.json, MAX BET/CANCEL 버튼 상태·키 포함) 통과
- 메인 씬·테스트 실행 로그에서 에러·경고 0
- 눈으로 봐야 하는 부분(라벨 위치, 깜빡임, 한글, 겹침)은 아직 미확인

### 가정
1. 라벨 위치: 가로·대각선은 시작 칸 높이의 왼쪽 + 끝 칸 높이의 오른쪽(같은 높이는 위아래로 쌓음), 세로(F·G·H)는 각 릴 위쪽에만 둔다 (아래쪽은 STOP 자리와 겹쳐 생략).
2. 당첨 선 색은 라인마다 다르고(화면 설정), 모든 당첨 라인이 동시에 3번(약 1.5초) 깜빡인 뒤 선과 흰 테두리는 다음 스핀·베팅 변경 때까지 남는다.
3. 크레딧 한도 때문에 BET이 안 올라갈 때는 순환하지 않고 안내만 한다 (순환은 최대 베팅에서만).
4. 안내 문구 아래줄에 "BET 8 이상이면 피버 적립"을 BET 8 미만일 때 항상 붙인다 (BET 0 포함).
5. WIN은 START 순간 0으로 지워지고 스핀 결과의 총 당첨금으로 채워진다.
6. 디버그 창은 기본 꺼짐(F1)으로 바꿨다 (2단계 가정 5번 변경). 켜면 화면 오른쪽 절반을 덮는다.
7. 심볼 그림 경로 규칙: `res://assets/symbols/cherry.png` 등 (`ICON_PATHS`). 폴더·파일은 아직 없다.
8. MAX BET은 베팅이 이미 목표값이면 아무 일도 하지 않는다(버튼도 비활성). 크레딧 0에서 M 키는 "크레딧이 없습니다" 안내만 띄운다. CANCEL은 베팅 0에서 아무 안내 없이 무시.
9. 배당표의 심볼 박스는 색만 쓰고(글자 없음) 이름은 옆에 따로 적는다. 나중에 그림 파일이 생기면 박스를 그림으로 바꿀지는 6단계에서 결정(확인 필요).

### 가정 (기획서에 명시되지 않아 정한 것)
1. 정지 위치 = 윗줄에 보이는 스트립 번호. 가운데 +1, 아랫줄 +2, 끝에서 처음으로 이어짐.
2. 피버 보너스의 "현재 총 베팅" = 피버가 발동한 스핀의 총 베팅.
3. 한 스핀에 피버 대상 심볼 여러 개가 당첨되면 각 심볼 카운터가 1씩 줄어든다.
4. 피버는 그 스핀에서 바로 판정·지급한다 (로직 확정, 화면은 정지 후 보여주기만).
5. 풀 적립은 베팅액과 관계없이 매 스핀. 획득만 BET 8 이상.
6. 풀 소수점(8 × 5% = 0.4)은 내부에서 누적하고, 표시·지급은 정수(버림). 획득 후 500으로 리셋(소수점도 버림).
7. 처리 순서: 풀 적립 → 라인 판정 → 피버 → (세븐 피버면) 풀 획득.
8. RTP = (라인 당첨 + 피버 보너스 + 풀 지급) ÷ 총 베팅.
9. 시뮬레이션은 크레딧 부족을 따지지 않는다.
10. 릴 스트립: 3칸 연속은 릴마다 체리·오렌지 1곳씩만, 나머지 심볼은 최대 2칸 연속.
