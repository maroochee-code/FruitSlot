# FruitSlot 진행상황

## 5단계 선행 과제 — 릴 연출 방식 변경 (계획 · 아직 시작 안 함)

5단계(피버·풀 연출)에 들어가기 전에 릴의 모양을 바꾼다. 4단계의 "릴 창 전체가 한 덩어리로 흐르는" 방식을 아래로 교체한다.
**연출만 바꾸고, 결과 확정 로직(`scripts/logic`, START 때 RNG로 한 번 확정)은 그대로 둔다.**

### 바꿀 것
1. **칸 단위 클리핑 창**
   - 9칸의 테두리는 **고정**한다 (회전 중에도 움직이지 않음).
   - 각 칸은 자기 칸 모양으로 잘라 보여 주는 창이고, 그 안에서 **심볼 두 개가 반쪽씩 걸쳐 스크롤**한다 (위 심볼의 아랫부분 + 아래 심볼의 윗부분).
   - **심볼이 칸 경계를 넘지 않는다.** 칸 밖으로 번지거나 이웃 칸과 겹쳐 보이지 않는다.
   - 4단계의 위아래 반 칸 덤 영역과 어두운 가림막은 이 방식에 맞게 없애거나 대체한다 (`half_row`의 의미도 함께 정리 — 확인 필요).
   - 영향 범위(예상): `reel_view.gd`, `symbol_cell.gd`(칸 클리핑), `main.gd`(칸 배치). `ReelMotion`의 위치 계산과 STOP·정산 흐름은 유지.
2. **릴별 출발 시간차·속도차를 `feel.json` 수치로 분리**
   - 릴마다 출발을 조금씩 늦추는 값과 릴마다 속도 배율을 둔다. 예: `reel_start_delay`(릴1~3), `reel_speed_scale`(릴1~3). 정확한 키 이름과 범위는 구현 때 정하고 사용자에게 확인 (확인 필요).
   - 자동 정지 시각의 기준(START)과 출발 지연의 관계를 정해야 한다 (확인 필요).
   - 4단계의 재로딩 규칙을 그대로 따른다: 다음 스핀부터 적용, 진행 중 스핀은 불변.
3. **결과 확정 로직은 그대로**: 정지 위치는 START 순간 확정, 연출은 거기까지 보여줄 뿐. 칸 단위 연출로 바꿔도 "보이는 심볼은 실제 릴 스트립 순서", "최종 화면 == 로직 결과"를 자동 테스트로 계속 보장한다 (STOP 시점·순서·자동·회전 중 START, 출발 지연·속도차 포함).

### 끝난 뒤
- 위 과제와 사용자 확인을 마친 뒤 **피버·풀 연출(5단계)** 을 진행한다.

### 검증
- 판정 44/44, 상태 56/56 (기존 50 + 신규 6), 릴 35/35, 화면 85/85 통과. 메인 씬 실행(Godot MCP)과 네 테스트 모두 에러·경고 0
- **결과 불변**: 릴 움직임 600회 + 컨트롤러 800회(입력 무작위: STOP 시각·순서, 자동 정지, 회전 중 START, 30/60/144fps·0.2초 튀는 프레임·무작위 손맛 값)에서 최종 정지 위치 == 목표 정확히 일치
- 화면 테스트 300회 스핀을 입력 4가지(자동 / 키 1·2·3 무작위 / 회전 중 START / 버튼·키·START 혼합)로 돌리며: 최종 칸 9개 == 로직 grid, 릴 위치 == `stops`, 회전 중 모든 프레임에서 심볼이 실제 스트립 순서, 정산 전 CREDIT·WIN·POOL·피버 불변, 회전 중 COIN/BET/MAX BET/CANCEL 무효
- 검사가 헛돌지 않는지 확인: 정지 위치를 일부러 어긋나게 / 정산을 앞당기게 고치면 해당 테스트가 실패함을 확인한 뒤 원복

### feel.json 실행 중 재로딩 (4단계에 포함)
- 파일 수정 시각을 0.5초마다 확인해 저장하면 자동으로 다시 읽고, **F6**은 즉시 다시 읽는다.
- 새 값은 "대기 설정"에 보관되고 **다음 START 때만** 적용된다. 한 스핀은 시작 때의 설정 한 벌로 끝까지 움직인다 (`ReelMotion.start`, `SpinController.begin`이 설정을 받음). `GameState`·로직은 손대지 않았으므로 결과 확정 규칙 그대로.
- 파일이 깨져 못 읽으면 이전 값 유지, 범위 밖 항목은 기본값 + 안내 문구(경고 로그 없음). `half_row`만 재시작 필요.
- 검증: 같은 시드로 3스핀을 두 번 돌려 비교. 첫 스핀 0.3초에 설정을 크게 바꿔도 그 스핀의 정지 위치·릴별 정지 시각이 바꾸지 않은 경우와 완전히 같고, 결과 순서도 같음. 다음 스핀부터 새 설정(속도 60, 자동 정지 1.0초)이 반영됨. 설정 교체를 일부러 막으면 4개 검사가 실패함을 확인한 뒤 원복.

### 가정
1. 자동 정지 시각은 START 기준(3.0, 3.4, 3.8초). 먼저 손으로 멈춘 릴은 건너뛰고 나머지 시각은 그대로.
2. 회전 중 START: 남은 릴을 왼쪽부터 `quick_stop_interval`(0.15초) 간격으로 차례로 정지. START 직후 0.3초는 무시. 두 번째 누름은 무시.
3. 감속 구간은 항상 `slide_cells`(3칸)로 같고, STOP 후 멈추기까지 대기는 목표 위치에 따라 0~한 바퀴(약 1.2초)+0.5초.
4. 정산은 마지막 릴이 멈춘 뒤 `result_delay`(0.25초) 지나서. 그 사이에도 조작 잠금 유지.
5. 처음 화면의 릴은 스트립 0번 위치 심볼을 보여줌 (이전에는 빈 박스). 이 위치는 결과와 무관.
6. 칸 높이 78, 릴 y 55로 변경 (사용자 승인). 세로 라인 라벨(F·G·H)은 위쪽 덤 영역 위에 겹쳐 그려진다 (확인 필요).
7. 회전 중 안내 문구: "STOP 1·2·3 또는 START로 릴을 멈추세요."
8. 회전 중 START 버튼은 정지시킬 릴이 남아 있으면 활성 (이름은 START 그대로).
9. 당첨금 카운트업 등 연출은 6단계.

### 남은 문제 / 눈으로 확인할 것
- 손맛(회전 속도, 감속, 튕김, 대기 시간)은 사용자 확인 필요. 수치는 `data/feel.json`만 고치면 됨.
- 라인 라벨 F·G·H가 위쪽 덤 영역(어두운 막) 위에 겹쳐 읽기 괜찮은지 확인 필요.
- 당첨 선·강조는 정산 직후에 켜지므로, 릴이 멈춘 직후 약 0.25초 비어 보이는 것이 어색한지 확인 필요(`result_delay`).

### 확인 방법 (F5)
0. (손맛 조절) 게임을 켠 채 `data/feel.json`의 `spin_speed`를 40으로 고쳐 저장 → 안내 문구에 "다음 스핀부터 적용"이 뜨고, 다음 START부터 빨라지는지 (F6은 즉시 다시 읽기)
1. F5 → `C`(COIN) → `M`(MAX BET) → 스페이스
2. 아무것도 안 누르면 약 3초 뒤 릴1, 릴2, 릴3 순서로 멈추는지
3. 1·2·3 키(또는 STOP 버튼)를 원하는 순서로 눌러 보기. 누른 뒤 미끄러지듯 멈추고 살짝 튕기는지
4. 회전 중 스페이스: 남은 릴이 왼쪽부터 차례로 멈추는지
5. 회전 중 C/B/M/X가 먹지 않고 버튼이 회색인지
6. 세 릴이 멈춘 뒤에야 WIN·크레딧·POOL이 바뀌는지

기획서 5·6장을 확정된 규칙에 맞게 고쳤다 (START 차감, BET 순환, 시작 크레딧 0, 자동 하향, WIN 총합).

### 사용자 확인 후 추가한 것 (같은 3단계에 포함)
- **MAX BET (M)**: 베팅 = min(최대 베팅, 현재 크레딧). 이미 그 값이면 비활성.
- **CANCEL (X)**: 베팅 0. 크레딧 변화 없음. 베팅이 이미 0이면 비활성.
- 버튼 줄: CANCEL / COIN / START / BET / MAX BET (버튼 폭 96→76, START 120→100, 글자 13).
- **배당표**: 피버 카운터 아래(y 260~416)에 7줄. 자리가 충분해 억지로 넣지 않았다. 제목에 "(3개 일치 × 라인 베팅)"을 적어 기준을 표시.
- 기획서 2·5·13장에 반영 (단축키 M, X 추가. 기존 C, B, 스페이스/엔터, 1/2/3, F1과 겹치지 않음).

### 검증
- 판정 테스트 44/44, 상태 테스트 50/50, 화면 테스트 40/40 (300회 스핀마다 칸·CREDIT·WIN·BET·POOL·피버·당첨 선 개수 일치, 배당표 숫자=balance.json, MAX BET/CANCEL 버튼 상태·키 포함) 통과
- 메인 씬·테스트 실행 로그에서 에러·경고 0
- 눈으로 봐야 하는 부분(라벨 위치, 깜빡임, 한글, 겹침)은 아직 미확인

### 가정
1. 라벨 위치: 가로·대각선은 시작 칸 높이의 왼쪽 + 끝 칸 높이의 오른쪽(같은 높이는 위아래로 쌓음), 세로(F·G·H)는 각 릴 위쪽에만 둔다 (아래쪽은 STOP 자리와 겹쳐 생략).
2. 당첨 선 색은 라인마다 다르고(화면 설정), 모든 당첨 라인이 동시에 3번(약 1.5초) 깜빡인 뒤 선과 흰 테두리는 다음 스핀·베팅 변경 때까지 남는다.
3. 크레딧 한도 때문에 BET이 안 올라갈 때는 순환하지 않고 안내만 한다 (순환은 최대 베팅에서만).
4. 안내 문구 아래줄에 "BET 8 이상이면 피버 적립"을 BET 8 미만일 때 항상 붙인다 (BET 0 포함).
5. WIN은 START 순간 0으로 지워지고 스핀 결과의 총 당첨금으로 채워진다.
6. 디버그 창은 기본 꺼짐(F1)으로 바꿨다 (2단계 가정 5번 변경). 켜면 화면 오른쪽 절반을 덮는다.
7. 심볼 그림 경로 규칙: `res://assets/symbols/cherry.png` 등 (`ICON_PATHS`). 폴더·파일은 아직 없다.
8. MAX BET은 베팅이 이미 목표값이면 아무 일도 하지 않는다(버튼도 비활성). 크레딧 0에서 M 키는 "크레딧이 없습니다" 안내만 띄운다. CANCEL은 베팅 0에서 아무 안내 없이 무시.
9. 배당표의 심볼 박스는 색만 쓰고(글자 없음) 이름은 옆에 따로 적는다. 나중에 그림 파일이 생기면 박스를 그림으로 바꿀지는 6단계에서 결정(확인 필요).
10. 피버 카운터는 balance.json의 심볼 이름(체리 ×20 식)으로 표시한다. 색·연출은 5단계.

### 남은 문제
- 위 가정 1~4는 화면에서 보고 판단 필요.
- 배당표 제목("배당표 (3개 일치 × 라인 베팅)")이 패널 폭 안에 들어오는지 눈으로 확인 필요. 넘치면 "배당 (라인 베팅 ×)"처럼 줄인다.
- 체리 피버 카운터가 20으로 시작해 "×20"이 보인다 (밸런스 1차 조정 결과, 기획서 초기값 5와 다름).
- 스핀이 즉시 끝나므로 스핀 중 입력 잠금은 없다 (4단계에서 추가).

2. 심볼 색은 밸런스 수치가 아니라 화면 설정이라 `symbol_style.gd` 상수로 둔다.
3. 난수 시드는 실행 시각(마이크로초)으로 정한다. 재현이 필요하면 시뮬레이션 씬을 쓴다.
4. 한글 글꼴은 시스템 글꼴(맑은 고딕 우선)을 쓴다. 웹 내보내기 단계에서는 글꼴 파일을 프로젝트에 넣어야 할 수 있다(확인 필요).

### 가정 (기획서에 명시되지 않아 정한 것)
1. 정지 위치 = 윗줄에 보이는 스트립 번호. 가운데 +1, 아랫줄 +2, 끝에서 처음으로 이어짐.
2. 피버 보너스의 "현재 총 베팅" = 피버가 발동한 스핀의 총 베팅.
3. 한 스핀에 피버 대상 심볼 여러 개가 당첨되면 각 심볼 카운터가 1씩 줄어든다.
4. 피버는 그 스핀에서 바로 판정·지급한다 (로직 확정, 화면은 정지 후 보여주기만).
5. 풀 적립은 베팅액과 관계없이 매 스핀. 획득만 BET 8 이상.
6. 풀 소수점(8 × 5% = 0.4)은 내부에서 누적하고, 표시·지급은 정수(버림). 획득 후 500으로 리셋(소수점도 버림).
7. 처리 순서: 풀 적립 → 라인 판정 → 피버 → (세븐 피버면) 풀 획득.
8. RTP = (라인 당첨 + 피버 보너스 + 풀 지급) ÷ 총 베팅.
9. 시뮬레이션은 크레딧 부족을 따지지 않는다.
10. 릴 스트립: 3칸 연속은 릴마다 체리·오렌지 1곳씩만, 나머지 심볼은 최대 2칸 연속.
