`scripts/logic/`은 수정하지 않았다. `project.godot`은 오토로드 한 줄만 추가했다.
기획서 5·6장을 확정된 규칙에 맞게 고쳤다 (START 차감, BET 순환, 시작 크레딧 0, 자동 하향, WIN 총합).

### 사용자 확인 후 추가한 것 (같은 3단계에 포함)
- **MAX BET (M)**: 베팅 = min(최대 베팅, 현재 크레딧). 이미 그 값이면 비활성.
- **CANCEL (X)**: 베팅 0. 크레딧 변화 없음. 베팅이 이미 0이면 비활성.
- 버튼 줄: CANCEL / COIN / START / BET / MAX BET (버튼 폭 96→76, START 120→100, 글자 13).
- **배당표**: 피버 카운터 아래(y 260~416)에 7줄. 자리가 충분해 억지로 넣지 않았다. 제목에 "(3개 일치 × 라인 베팅)"을 적어 기준을 표시.
- 기획서 2·5·13장에 반영 (단축키 M, X 추가. 기존 C, B, 스페이스/엔터, 1/2/3, F1과 겹치지 않음).

### 검증
- 판정 테스트 44/44, 상태 테스트 50/50, 화면 테스트 40/40 (300회 스핀마다 칸·CREDIT·WIN·BET·POOL·피버·당첨 선 개수 일치, 배당표 숫자=balance.json, MAX BET/CANCEL 버튼 상태·키 포함) 통과
- 메인 씬·테스트 실행 로그에서 에러·경고 0
- 눈으로 봐야 하는 부분(라벨 위치, 깜빡임, 한글, 겹침)은 아직 미확인

### 가정
1. 라벨 위치: 가로·대각선은 시작 칸 높이의 왼쪽 + 끝 칸 높이의 오른쪽(같은 높이는 위아래로 쌓음), 세로(F·G·H)는 각 릴 위쪽에만 둔다 (아래쪽은 STOP 자리와 겹쳐 생략).
2. 당첨 선 색은 라인마다 다르고(화면 설정), 모든 당첨 라인이 동시에 3번(약 1.5초) 깜빡인 뒤 선과 흰 테두리는 다음 스핀·베팅 변경 때까지 남는다.
3. 크레딧 한도 때문에 BET이 안 올라갈 때는 순환하지 않고 안내만 한다 (순환은 최대 베팅에서만).
4. 안내 문구 아래줄에 "BET 8 이상이면 피버 적립"을 BET 8 미만일 때 항상 붙인다 (BET 0 포함).
5. WIN은 START 순간 0으로 지워지고 스핀 결과의 총 당첨금으로 채워진다.
6. 디버그 창은 기본 꺼짐(F1)으로 바꿨다 (2단계 가정 5번 변경). 켜면 화면 오른쪽 절반을 덮는다.
7. 심볼 그림 경로 규칙: `res://assets/symbols/cherry.png` 등 (`ICON_PATHS`). 폴더·파일은 아직 없다.
8. MAX BET은 베팅이 이미 목표값이면 아무 일도 하지 않는다(버튼도 비활성). 크레딧 0에서 M 키는 "크레딧이 없습니다" 안내만 띄운다. CANCEL은 베팅 0에서 아무 안내 없이 무시.
9. 배당표의 심볼 박스는 색만 쓰고(글자 없음) 이름은 옆에 따로 적는다. 나중에 그림 파일이 생기면 박스를 그림으로 바꿀지는 6단계에서 결정(확인 필요).
10. 피버 카운터는 balance.json의 심볼 이름(체리 ×20 식)으로 표시한다. 색·연출은 5단계.

### 남은 문제
- 위 가정 1~4는 화면에서 보고 판단 필요.
- 배당표 제목("배당표 (3개 일치 × 라인 베팅)")이 패널 폭 안에 들어오는지 눈으로 확인 필요. 넘치면 "배당 (라인 베팅 ×)"처럼 줄인다.
- 체리 피버 카운터가 20으로 시작해 "×20"이 보인다 (밸런스 1차 조정 결과, 기획서 초기값 5와 다름).
- 스핀이 즉시 끝나므로 스핀 중 입력 잠금은 없다 (4단계에서 추가).

### 다음 단계
- 4단계: 릴 회전과 STOP 1/2/3, 자동 정지, 감속 연출

### 검증
- 메인 씬 실행(headless 120프레임): 에러·경고 0
- `view_test`: START 200회 중 화면 칸≠로직 결과 **0회**, 결과 없음 0회

### 가정
1. 베팅 UI가 없으므로 START는 `balance.json`의 `fever_min_total_bet`(풀베팅 8)으로 스핀한다. 크레딧은 아직 없다(3단계).
2. 심볼 색은 밸런스 수치가 아니라 화면 설정이라 `symbol_style.gd` 상수로 둔다.
3. 난수 시드는 실행 시각(마이크로초)으로 정한다. 재현이 필요하면 시뮬레이션 씬을 쓴다.
4. 한글 글꼴은 시스템 글꼴(맑은 고딕 우선)을 쓴다. 웹 내보내기 단계에서는 글꼴 파일을 프로젝트에 넣어야 할 수 있다(확인 필요).
5. 디버그 창은 오른쪽 패널 위에 겹쳐 그린다(기본 켜짐). 끄면 3단계 자리(POOL·피버)가 보인다.
6. 라인 라벨 자리는 릴 좌우에 4칸씩, 위치는 임시다. 3단계에서 각 라인 끝 위치에 맞춰 조정한다.

### 확인 필요 / 남은 문제
- RTP 92.65%는 범위 하한에 가깝다 (이론값 93.2%, 세븐·풀 표본 오차). 더 올리려면 포도 배수 30→35(+약 1.2%p).
- 대각(9.6%) vs 세로(9.4%) 당첨 횟수 차이가 근소하다. 세로 RTP(17.48%)와 대각(17.77%)도 근접.
- 풀 RTP는 목표(8%)보다 낮다 (적립률 5%의 구조적 값).
- 가로 RTP가 높아 BET 1~5도 RTP 약 71%다 (BET 8의 92.65%보다는 확실히 낮음).
- 체리 카운터 20은 기획서 초기값(5)과 크게 다르다. 5단계 화면 설계 때 표시 방식 확인.

### 가정 (기획서에 명시되지 않아 정한 것)
1. 정지 위치 = 윗줄에 보이는 스트립 번호. 가운데 +1, 아랫줄 +2, 끝에서 처음으로 이어짐.
2. 피버 보너스의 "현재 총 베팅" = 피버가 발동한 스핀의 총 베팅.
3. 한 스핀에 피버 대상 심볼 여러 개가 당첨되면 각 심볼 카운터가 1씩 줄어든다.
4. 피버는 그 스핀에서 바로 판정·지급한다 (로직 확정, 화면은 정지 후 보여주기만).
5. 풀 적립은 베팅액과 관계없이 매 스핀. 획득만 BET 8 이상.
6. 풀 소수점(8 × 5% = 0.4)은 내부에서 누적하고, 표시·지급은 정수(버림). 획득 후 500으로 리셋(소수점도 버림).
7. 처리 순서: 풀 적립 → 라인 판정 → 피버 → (세븐 피버면) 풀 획득.
8. RTP = (라인 당첨 + 피버 보너스 + 풀 지급) ÷ 총 베팅.
9. 시뮬레이션은 크레딧 부족을 따지지 않는다.
10. 릴 스트립: 3칸 연속은 릴마다 체리·오렌지 1곳씩만, 나머지 심볼은 최대 2칸 연속.

### 남은 문제
- **RTP 142%로 목표 초과.** 주원인은 체리 피버(56.6%)와 세로 라인(29.4%). 조정 여부는 사용자 결정 대기.
- 세븐 관련 표본이 작다 (10만 회에 11회). 풀·세븐 수치를 판단하려면 100만 회 이상을 권장.
- 크레딧·COIN·BET 버튼 상태는 3단계에서 `GameState`(전역 싱글톤)로 만든다.
